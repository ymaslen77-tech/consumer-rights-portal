## Незавершённые задачи

1. **Coolify/VPS:** приложение `consumer-web` ранее открывалось на VPS и успешно отвечало на шесть HTTP-проверок. После расширения до 101 маршрута пользователь сообщил о ручном Redeploy, но фактический SHA нового контейнера и работа всех новых маршрутов ещё требуют серверной проверки. Для последующих релизов `/api/health` показывает `SOURCE_COMMIT` Coolify и фактический состав контента, если переменная доступна. Если `sourceCommit=null`, нельзя утверждать, какая версия развёрнута.
2. **Юридическая точность:** 84 ситуационный маршрут требуют предметной сверки условий, сроков, исключений и переходных правил. Сверка статей и источников не означает, что каждый персональный иск готов к подаче. См. `docs/LEGAL_GENERATORS_AUDIT_2026-11-02.md`, issue #6.
3. **Судебные решения:** добавить реальный сбор, чтение и проверку полных официальных текстов с защитой персональных данных, реестром реквизитов и учётом результатов апелляций; валидатор PR #11 выполняет лишь структурные проверки.
4. **Данные и публикация:** расширить справочник региональных органов и новости, внедрить независимую редакционную CMS/БД при подтверждённой необходимости. Пока данные в JSON; личных кабинетов и серверного хранения черновиков нет.
5. **Публичный релиз:** отдельный домен, HTTPS, резервирование, privacy/SEO и явная санкция владельца. См. issue #2; его ранняя формулировка об отсутствии приложения могла устареть.

### Принцип правовой приёмки

Нормативную информацию сверять по действующей редакции официального источника, при необходимости по 2–3 надёжным независимым материалам. Совпадающую подтверждённую справочную информацию можно маркировать проверенной. Для претензии/иска оставлять отдельные фактические условия (срок, товар, статус стороны, необходимые приложения и т.п.) и **не** выставлять `READY_TO_FILE` автоматически.

## Coolify — безопасный порядок

1. Открыть существующий проект `consumer-rights-portal` и приложение `consumer-web` (или установить, что его нет); **не изменять** другие проекты.
2. Сверить `infra/coolify-russian-vps`, `/Dockerfile.coolify`, порт `3000`, проверку `GET /api/health`, отсутствие Auto Deploy.
3. Для закрытого preview использовать `SITE_CUTOVER=false`, `SITE_RELEASE_APPROVED=no`, `SITE_URL=`, `PUBLIC_RELEASE_HOST=`; предварительная публикация остаётся `noindex`.
4. После зелёных проверок на точном merge SHA вручную выполнить изолированный Deploy, подтвердить URL, health, основные страницы, DOCX и браузерное сохранение в PDF. Сохранить предыдущий исправный релиз для отката.
5. Только после отдельного решения владельца настроить публичный HTTPS-хост и разрешить индексацию.

Приложение `consumer-web` можно регистрировать по процедуре `docs/COOLIFY_ONE_TIME_SETUP.md`, **только если предварительный read-only осмотр подтверждает его отсутствие**. Не использовать секреты/БД/домены ДГИ, Судов или ПравоПоиска.
