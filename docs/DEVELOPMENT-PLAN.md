# Этапы дальнейшей разработки «Защиты прав потребителей»

**Принцип:** копировать *проверенные технические решения ДГИ*, не переносить жилищные/судебные данные ДГИ, Webflow legacy CMS, чужие домены/Яндекс.Метрику/секреты.

## Этап 1: готов прототип (этот архив)
- Системы: Next.js 16 / React 19, CSS, модели JSON.
- 20 направлений / 60 ситуаций / 10 черновиков документов / 8 карточек учреждений.
- Все карточки привязаны к URL официального первоисточника; специально исключены фиктивные телефоны/адреса.
- Базовые маршруты, SEO и закрытая индексация.

## Этап 2: переиспользование эталона ДГИ
- После создания самостоятельного репозитория клонировать исходную кодовую базу DGI в отдельную рабочую копию (без доступа к production).
- Сопоставить шаблоны страниц, единый PageShell, Payload CMS, PostgreSQL, роли, guarded reads и CI.
- Сохранить один доменный конфиг, централизованные источники, типизированные статусы материалов.
- Мигрировать 20/60/10/8 из данного прототипа в структуру `apps/web/src/data` реплики.
- Полностью удалить привязки к DGI: brand, data, host allowlist, версию sitemap, метрику, внешние старые страницы, SEO, судебные URL.

## Этап 3: юридическая структура
- Разработать 60 ситуаций (начать с 20 приоритетных) как алгоритмы с выбором требований, исключениями, доказательствами, сроками, документами и результатами.
- В каждом материале хранить источник нормы и редакцию *с датой действия*; проверка официального текста обязательна до пометки юридической готовности.
- Внести специальные схемы для дистанционных продаж, технически сложных товаров, финансовых услуг, ЖКХ, медицинских услуг и транспорта.

## Этап 4: генераторы документов и судебная практика
- Генераторы претензий/исков с условными полями и валидаторами; PDF/DOCX после тестирования, исходные формы доступны для сверки.
- Начать с федеральной ГИС ЗПП и официальных судебных сайтов; не импортировать метаданные как полный судебный акт.
- Реквизиты, исход, обособленные PDF, SHA-256, персональные данные, право на публикацию, парсер под конкретный суд.

## Этап 5: ведомства и контакты РФ
- Импорт только проверенных адресов, графиков, электронных способов обращения по региональным официальным страницам.
- Общественные объединения из реестра ГИС ЗПП: независимый статус, контакты и платность услуг проверять по первоисточнику; не представлять как госорган.
- Мониторить изменение номеров, переходы, устаревшие страницы. Неверифицированную карточку не публиковать.

## Этап 6: news / SEO / CI / релиз
- Не более пяти оригинальных материалов в выпуске; официальные источники и антидубли.
- Защищённая ветка `infra/coolify-russian-vps`, PR, `web-checks`, `db-checks`, `cms-checks`, `approval-policy`, исходные/судебные проверки.
- Успешный CI на **точном финальном SHA**, merge по ruleset; отсутствие Deploy-on-push в Coolify.
- Владелец вручную нажимает Deploy; HTTP smoke и мониторинг. Только подтверждённое live считается опубликованным.

## Критерии изоляции
- Новый GitHub/DB/Coolify/домен, отдельная аналитика, резервные копии, ключи.
- Ни одного DGI-контентного JSON, персональных данных и архивов по умолчанию.
- Отдельные роли Payload. Никакого права публиковать редакционные черновики от наличия таблиц.
