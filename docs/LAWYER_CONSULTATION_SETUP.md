# Юридическая консультация и проверка документа

## Что уже реализовано

- На всех страницах виджет «Консультация юриста».
- Приблизительное количество активных вкладок на **текущем серверном процессе**: анонимный UUID вкладки, периодическое подтверждение присутствия, срок активности 120 секунд. Без передачи Ф. И. О., адреса, текста документа, IP в базу данных; статистика не сохраняется после рестарта. Это **не подтверждение онлайн-присутствия юриста** и не полноценная аналитика уникальных людей.
- Под каждым документом кнопка «Отправить на проверку юриста». В форме есть отдельное подтверждение передачи данных.
- Консультационный запрос и документ передаются **только** при подключении реального HTTPS-webhook, включённой опции, HTTPS самого сайта и явном согласии пользователя. Иначе сервер отвечает `503 unavailable`, а форма сообщает, что заявка не отправлена.
- Сохранение DOCX, TXT и PDF остаётся локальным и не вызывает передачу персональных данных.
- На незащищённом временном HTTP-домене приём любых заявок отключён, даже если оператор ошибочно установит параметры webhook.

## Что требуется перед включением юридической проверки

1. Определить реального ответственного юриста/службу и согласовать, кто получает заявки и в какие сроки отвечает. **Не выдавать автоматическую форму за подтверждение доступности юриста.**
2. Подготовить политику обработки персональных данных, согласие и правила хранения/удаления; оценить применимые требования к ПДн для РФ. Утвердить приём из формы и обработку вложений/текста.
3. Настроить проверенный **HTTPS-домен** для пользовательского интерфейса, не адрес `sslip.io` по HTTP.
4. Подключить отдельный проверенный внутренний HTTPS endpoint-получатель, который принимает `POST` JSON:
   - HTTP header: `Authorization: Bearer <secret>`
   - `kind`: `document` или `consultation`
   - `title`, `text`, `contact`, `consent: true`
   - `requestId`, `receivedAt`
   Получатель должен вернуть HTTP 2xx **только после надёжного принятия заявки**. При ошибке сайт покажет отказ без ложного подтверждения.
5. Задать **только в Coolify runtime** для приложения `consumer-web`:
   - `LAWYER_REVIEW_WEBHOOK_URL=https://<проверенный-получатель>`
   - `LAWYER_REVIEW_WEBHOOK_TOKEN=<отдельный-секрет>`
   - `LAWYER_REVIEW_ENABLED=true`
   Значения не помещать в GitHub, скриншоты или чат. Не копировать секреты других проектов.
6. Проверить реальную доставку тестовой заявки с вымышленными данными, факт получения, права на доступ, удаление и ограничение частоты запросов.

## Безопасность и ограничения

- Само добавление этой функции в GitHub **не включает** пересылку документов и не создаёт адрес для юридической помощи.
- По умолчанию включён `LAWYER_REVIEW_ENABLED=false`; в CI отрабатывает проверка отказа в отправке и анонимного присутствия.
- Анонимный счётчик приблизительный: учитывает вкладки, а не людей; на нескольких репликах не суммирует все процессы. Не отображает «юрист онлайн» без отдельного подтверждённого канала.
- Канал передачи JSON, без файловых вложений. Текст создаётся в браузере, затем при согласии отправляется оператору через серверный endpoint.
- На стороне сайта введены ограничения на размер сообщения и число попыток, но для публичного запуска необходимы также спам-защита, аудит доставок и безопасность webhook.
- Пока HTTPS и политика обработки данных не готовы, лучше оставить консультационную форму в состоянии «приём не подключён» и использовать подтверждённые внешние справочники.
